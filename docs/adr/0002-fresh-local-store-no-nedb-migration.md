# 2. Rust 版使用全新本地存储，不迁移 NeDB 缓存

日期: 2026-10-19
状态: 已接受（Q3=A+B）

## 背景

现实现本地缓存为 NeDB JSONL（`nedb55/users.db`、`nedb55/<userId>/*.db`）+ 二进制目录（`data/<userId>/{images,attachs}`）。Rust 版需要新的存储选型。旧缓存是否迁移是必须现在定的分叉：迁移意味着读 NeDB 追加式 JSONL（含 NeDB 特有旧行为）、脏标记语义复刻、以及 `LastSyncUsn` 等同步断点的精确继承；不迁移则 Rust 版首启重新全量同步。

## 决策

1. **线协议**与 leanote 服务器 100% 兼容（同一账号在 Electron 版与 Rust 版可互换使用）。
2. **本地存储换新**：Rust 版自选存储（选型在实现时定，倾向 SQLite），目录不与 NeDB 版共享，不写 NeDB 格式。
3. **不迁移旧缓存**：Rust 版登录后执行一次全量同步重建本地状态。
4. CLI 的“应用未运行时直接写存储”双模（Q2=A 要求保留）因存储格式改变而失效：Rust 时代 CLI 直写路径指向 Rust 存储；过渡期内 Electron 版与 Rust 版**不同时运行**由用户保证（Q6=B：JS 版冻结，Rust 版为准）。

## 后果

- 正：不必实现 NeDB 读取器；脏标记/冲突语义可以在新存储里重新设计得更干净；`tests/` 的 MCP/API 测试照跑（它们走 HTTP，不碰存储）。
- 负：Electron 版退出历史后，其本地缓存里的未同步脏数据必须先同步完再切换（一次性人工动作）；CLI 离线直写需要按新存储实现一遍。
- 双版本并行期（Q5=A）同一账号的同步语义：两边都以服务器为权威，互换使用不丢数据（USN 增量同步保证），但本地未推送的脏数据只存在于产生它的客户端。
